# `hooks/agent-notification-say` 仕様

## 概要

ツール実行の許可待ち（permission prompt）が発生したタイミングで、macOS の `say` コマンドを使って短い日本語の音声通知を行う。ユーザーレベル（グローバル）フックで、プロジェクト単位の設定や `.env` ファイルには依存しない。

Cursor では許可プロンプト表示専用イベントが無いため、承認待ち通知ではなく「ツール実行前通知」として扱う。

対応先の詳細な連携方式（対応イベント名・相乗り方式の制約）は [../architecture.md](../architecture.md) の「対応エージェント」節を参照。

## 起動方法

```
agent-notification-say.sh <tool>
```

- `<tool>`: 必須の第1引数。エージェント識別子（`claude` / `codex` / `cursor` / `copilot` / `opencode` を想定）。未指定の場合はエラーで終了する。
- 標準入力から、各エージェントの Notification/PermissionRequest 系フックが渡す JSON ペイロードを読み取る（読み取れなくてもエラーにはしない）。

## 入出力仕様

### 入力（stdin）

JSON オブジェクト。使用するのは以下のフィールドのみ:

- `.message`（string, 任意）: 通知メッセージ本文。存在すればそのまま読み上げに使う。

### 出力

- 標準出力・標準エラーへの通常出力はなし（`afplay`/`say` の出力は `/dev/null` に捨てる）。
- 副作用として macOS の音声合成（`say`）とシステムサウンド再生（`afplay`）を行う。

### 終了コード

- 常に `0` を返す。これは意図的な仕様であり、通知が失敗してもエージェント本体の許可プロンプト処理を絶対に遅延・ブロックしてはならないため。

## 早期リターン条件（no-op になるケース）

以下のいずれかに該当する場合、何もせず `exit 0` する:

1. `uname -s` が `Darwin` でない（macOS 以外）
2. `say` コマンドが存在しない
3. `ENABLE_HOOKS` が `true` でない（スクリプト内ハードコード、現状は常に `true`）
4. `ENABLE_REPORT` が `say` でない（スクリプト内ハードコード、現状は常に `say`）

## メッセージ生成ロジック

1. `jq` が利用可能かつ stdin にペイロードがある場合、`.message` フィールドを取り出す。
2. `.message` が空の場合、フォールバックメッセージ `"${tool} がツールの実行許可を求めています。"` を使う。ただし `<tool>` が `cursor` の場合は `"${tool} がツールを実行します。"` を使う。
3. 得られたメッセージは改行を空白に置換し、先頭1000文字に切り詰める（`raw`）。
4. `<tool>` が `cursor` の場合、承認待ちを示す文言を使わず、読み上げ冒頭を `"ツールを実行します。"` にする。

LLMによる要約は行わない（`agent-report-say` と異なる点）。通知メッセージは元々短いという前提。

## 読み上げシーケンス（`speak()`）

1. `Sosumi.aiff` システムサウンドを再生
2. `say "確認をお願いします。"`
3. `say "<raw メッセージ>"`
4. `Bottle.aiff` システムサウンドを再生

Cursor では `say "確認をお願いします。"` の代わりに `say "ツールを実行します。"` を使う。

`speak` はバックグラウンド実行（`&` + `disown`）される。呼び出し元フックの処理をブロックしない。

Cursor では `hooks/lib/say-control.sh` が読み込める場合、0.5秒のデバウンスを行う。`conversation_id` または `transcript_path` からセッションを識別できる場合のみ、同一セッションの先行読み上げ worker を停止する。`workspace_roots[0]` しか無い場合はデバウンスのみ行い、先行読み上げは停止しない。

## 非機能要件

- 冪等性: 同一メッセージで複数回呼ばれても副作用は音声再生と Cursor 向け制御状態の更新のみである。
- 非ブロッキング: 呼び出し元（許可プロンプト自体の判定処理）を待たせてはならない。読み上げは必ずバックグラウンド化する。
- フェイルセーフ: どのステップで失敗しても（`jq` 不在、ペイロード不正、`say`/`afplay` の失敗等）、最終的に `exit 0` で終わる。
